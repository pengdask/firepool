# 日常管理与恢复

由 Agent 执行命令，用户用自然语言提出需求。CLI 为 `node <skill-directory>/scripts/firepool.mjs`，具体参数见 --help。

## 查询与管理

list 离线返回 summary 和 accounts：summary 是统一汇总，不是新增 Key 的单独验证报告。账户状态如下：

| 状态 | 含义与后续 |
| --- | --- |
| ready | 缓存有效且有余额，正常使用 |
| stale | 余额缓存过期，余额只供参考；实际领取按需检查 |
| unverified | 尚未验证，不能宣称可用 |
| unknown | 查询结果未知，不等于余额为零 |
| disabled | 用户手动停用，保留凭证，不自动启用 |
| invalid | 认证失效，修复后明确 enable 才恢复 |
| exhausted | 已知额度耗尽，5 分钟后可复查 |
| rate_limit / temporary | 冷却，说明 retryNotBefore 的本地时间 |

“查一下 Key 情况”默认 list；“查最新余额”执行 refresh 后 list。不要把多个 Key 的余额相加宣称为可用总额度，同一团队可能共享余额。缓存并非额度预留，实际请求结果为准。

新增 Key 用 setup --stdin 合并。停用、恢复、移除分别用 disable、enable、remove --id ID；使用账号标识即可，不需要用户再提供 Key。移除只操作明确指定的账号，不清空整个池。单个 Key 验证失败不影响其他账号。

## 更新与迁移

普通使用不检查远程版本、不重复安装。用户要求更新或当前版本缺少必要功能时：

- 由 install.mjs 安装的目录：下载新版完整包后运行安装器。只有旧目录所有文件都匹配原安装清单才替换；存在修改、额外文件、缺失文件或并发安装时停止，保留原目录。完成前使用同级临时目录，失败尝试恢复原目录。
- 同源 Git 克隆：确认来源及工作区干净后 fast-forward，不使用 reset --hard；本地修改保留并说明冲突。
- 客户端包导入：使用该客户端的更新机制，不猜目录或删除旧技能。

升级代码不搬动用户配置目录。不要因换 Agent 建第二套账号池；检查既有 FIREPOOL_HOME 和本机默认数据位置，先复用，再合并新 Key。新主机、云端宿主及不同系统用户不自动共享本机数据。

安装中断留下 .install.lock 时，先确认没有安装器运行，再移除对应锁。若存在 .previous-* 备份和 .install-* 临时目录，确认原版本内容后恢复；不要盲删未知目录。

## 故障与隐私

先看固定错误码、脱敏 list 与 [接入协议](protocol.md)。报告只含版本、系统、错误码、账号标识和状态，不附 Key、credentials.json、私有网址、完整环境变量或原始工具输出。

invalid_storage / existing_pool_unreadable：保留损坏文件，停止写入，按协议从用户自己的备份恢复；不静默重建。lock_timeout：确认进程停止后再处理锁。依赖下载失败不修改系统代理、VPN、DNS 或路由。目标网页验证码或拒绝访问不会通过轮换账号解决。

凭证保存在用户系统配置目录，Unix 目录 0700 / 文件 0600；Windows 使用当前用户目录 ACL。本地明文存储不能防御同用户恶意程序。直接粘贴是允许的；firepool 不回显凭证，也不能清除宿主已保存的聊天记录。需要保持新 Key 不进对话时用本机输入页。

## 卸载

“卸载 firepool”默认只移除宿主中的 Skill，保留账号池，便于重装；说明该用户目录内的凭证和调用工具仍在。不要修改其他业务工具或其他 Agent。

只有用户明确要求同时删除本地账号数据时，先停止 firepool 进程，再删除已确认的用户数据目录；不要把下载目录、整个用户配置目录或来源不明的 FIREPOOL_HOME 当成可直接删除对象。已经创建的远程任务、服务端账号和凭证不会因卸载自动撤销。
